# 상권 비교 대시보드 — 합의 명세

> 데이터는 샘플이다. 앱은 특정 행 값이 아니라 **컬럼 이름 + 설정 파일**로 동작한다.
> 설정: `config/settings.yaml`(기준값) · `columns.yaml`(컬럼 이름) · `metrics.yaml`(지표 계산) · `items.yaml`(비교 행) · `variables.csv`(요인 사전)

## 1. 공통 규칙

| 항목 | 내용 |
|---|---|
| 비교 기간 | 데이터 마지막 달부터 **1년** (샘플: 25.08~26.07). 요인 값도 같은 1년 |
| 가게 수 | 최근 달 기준 |
| 서울 보통 | 같은 업종 가게가 최근 달 3곳 이상인 서울 상권들의 중앙값 |
| 업종 선택 | 대분류 / 중분류. 중분류에 **전체** 추가 → 요인 표 `중분류 = 전체`, 상권 지표 `중분류 = 전체` 행을 쓴다. 없으면 "데이터가 아직 없어요" (`total_fallback`) |
| 표본 기준 | 상권의 같은 업종 가게가 3곳 미만이면 하이라이트 요약을 만들지 않는다 |

## 2. 업종별 5가지 요인 카드

- 요인 표에서 고른 업종의 순위 1~5. 제목·부제·하단 문구는 명세 문구 그대로
- 관계 모양(shape) 결정 순서: 요인 표 shape 컬럼 → `variables.csv` shape → 방향 텍스트(↑ 증가형, ↓ 감소형)
- **관계 확인 불가**: shape 가 optimum 인데 최적값이 없을 때(샘플: 주말·오후), 방향이 "뚜렷하지 않음/불안정"일 때 → 곡선 아이콘·관계 문장 대신 "관계 확인 불가"
- 관계 문장 템플릿: increasing "{threshold}보다 높아질수록 매출이 높아지는 편이에요"(임계값 없으면 "높을수록 매출이 높은 편이에요") / decreasing "높을수록 매출이 낮은 편이에요" / optimum "{optimum} 근처일 때 매출이 가장 높고, 그보다 많거나 적으면 낮아져요" / binary "{행동}하는 가게가 안 하는 가게보다 매출이 높은 편이에요"
- 신뢰도 "낮음": 대분류(전체) 요인 행이 있으면 그걸 쓰고 "대분류 기준이에요", 없으면 중분류 결과 + 경고

## 3. 매출 요인 하이라이트

- 쓰는 요인: 5가지 중 관계 확인 불가를 뺀 요인
- 효과 점수(매출 % 환산): `effect = 방향 크기 × (상권 값 − 서울 보통 값) ÷ (서울 상권 값의 p75 − p25)`
- 상대 차이: `gap = effect(이 상권) − 평균(effect(나머지 고른 상권))`
- 가장 유리 = gap 최대(≥ +5), 가장 불리 = gap 최소(≤ −5), 같으면 요인 순위가 높은 쪽
- 못 미치면 "▲ 다른 두 곳보다 뚜렷하게 앞서는 점 없음" / "▼ 다른 두 곳보다 뚜렷하게 뒤처지는 점 없음"
- 한 문장: `{best.factor} {best.value} · {worst.factor} {worst.value} — LLM 한줄 해석 연결 예정` (API 연결 시 명세의 JSON 입력 + `variables.csv` high_text/low_text 를 few-shot 으로)
- 1곳만 고르면 단일 진단: 요인별 서울 보통 대비 gap → 유리(≥ +5) / 보통 / 아쉬움(≤ −5)
- 각주: "'가장 유리 · 가장 불리'는 요인과 매출의 관계에 비춰, 고른 상권끼리 비교한 결과예요. 다른 곳과 차이가 5%p 미만이면 표시하지 않아요."

## 4. 비교 항목

| 섹션 | 항목 | 정의 | 비교 |
|---|---|---|---|
| 지도 | 상권 지도 | 격자 파일 경계. 이름 = 동 1개 · 대표 도로(대로 > 로 > 길, 같은 급이면 경계 안 길이 순, 같은 구에서 겹치면 다음 도로). 도로 없으면 동 1~2개. 상권 번호는 화면에 표시하지 않음 | 선택 칸 |
| 매출 | 매출 요인 하이라이트 | 3장 | 고른 상권끼리 |
| 매출 | 가게당 월매출 | sum(매출) ÷ sum(가게 수), 1년 | 서울 보통(같은 중분류 상권 중앙값) 대비 ±% + 막대 + 가장 높음. (세부 업종 기준 비교는 쓰지 않음) |
| 경쟁 | 동종업계 가게 수 | 최근 달 대분류 합 · 중분류 합 ("음식점 181곳 · 한식 82곳") | 값 |
| 경쟁 | 동종업계 밀집도 | 대분류 · 중분류 가게 수(최근 달) ÷ (격자 수 × 0.0625㎢) → 1㎢당 n곳, 두 값을 나란히 ("전체"면 대분류만) | 각 값 아래 서울 보통, 고른 업종 값에 가장 빽빽함 태그 |
| 경쟁 | 신규 매장 1년 생존율 | `survival_1y_pct` (향후 추가) | 서울 보통 대비 유리/보통/아쉬움 |
| 고객 (카드 결제 기준) | 매출 몰리는 시간대 · 요일 | 시간대 5개 비중(매출 가중) + 주말 비중 | 상권별 |
| 고객 (카드 결제 기준) | 주요 고객층 | 성별 2 × 나이 3 히트맵, 상위 3 | 상권별 |
| 비용 | 평균 임대료 | `rent_per_m2` (향후 추가, 상권 단위) | 구 평균 · 서울 보통 |
| 기타 | 검색 트렌드 | `trend_keywords` (상권 단위, 네이버 검색 상승 키워드, "a, b, c") | 칩 최대 3개, '#' 없이. 없으면 "–" |

향후 추가 컬럼은 데이터에 없으면 "데이터 확보 시 채워져요"로 자동 표시된다.

## 4-1. 상권 상세 (1년 트렌드) — 문구·구성: `config/detail.yaml`

| 섹션 | 내용 | 정의 |
|---|---|---|
| 머리말 | "{상권}에서 {업종}을/를 준비한다면", 상권 전환, 분석 기간 | 비교에서 고른 상권 |
| 비교 방식 | 최근 3개월 vs 최근 1년 | 데이터가 15개월 이상이면 최근 3개월 vs 전년 동기로 자동 전환 (`settings.yaml → trend`) |
| 01 성장 | 총매출 · 점포 수 · 점포당 평균 매출 변화 카드 + 월별 추이(첫 달 = 100) | 매출·점포 수는 기간 월평균, 점포당 = 매출 합 ÷ 점포 수 합 |
| 01 성장 | 헤드라인 | LLM 자리 표시 (총매출·점포 수·점포당 변화 값) |
| 02 소비 · 누가 | 성별×나이 6칸 중 비중이 가장 많이 오른 칸 (1%p 미만이면 "비슷한 편" + 가장 큰 고객층) | 카드 결제 고객 비중, 고객층 매출액 = 월평균 매출 × 비중 |
| 02 소비 · 언제 | 시간대 5구간 중 비중이 가장 많이 오른 시간대 + 주말 비중 변화 (요일×시간 조합은 데이터 없음) | 매출 비중 |
| 03 관심 | 인스타 해시태그 | `sns_hashtags_main`(지명, 최대 4) → `sns_hashtags_detail`(세부, 최대 5) 순서로 최대 9개. 띄어쓰기 구분 |
| 04 준비 방향 | 카드 3개: 언제 · 누가 · 경쟁(점포 수·점포당 매출·업종 1순위 요인) | 근거 문장·칩은 데이터, 제목은 LLM 자리 표시 |
| 표본 | 업종 가게 3곳 미만이면 "변화가 크게 흔들릴 수 있어요" 안내 | |
