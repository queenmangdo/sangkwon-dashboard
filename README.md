# 상권 매출 요인 대시보드 — 인수인계 README

> 지금 들어 있는 데이터는 **샘플(가데이터)**이에요. 앱은 특정 행 값이 아니라 **컬럼 이름과 설정 파일**로 동작하도록 만들어서,
> 실제 데이터로 바꿀 때 코드보다 `config/` 를 먼저 보면 돼요.
> 합의된 기획 내용은 `docs/SPEC.md`, 디자인 기준은 `design/STYLE.md` 에 있어요.

---

## 1. 무엇을 하는 앱인가

서울 상권(250m 격자 묶음)을 업종(대분류 › 중분류) 기준으로 비교하는 Streamlit 대시보드예요. 화면은 두 개예요.

| 화면 | 하는 일 |
|---|---|
| **상권 비교** | 상단에서 업종을 고르고, 지도 팝업에서 상권을 1~3곳 골라 같은 항목으로 나란히 비교. 맨 위에 업종별 매출 요인 5가지 카드, 매출 요인 하이라이트(가장 유리·불리) |
| **상권 상세** | 비교에서 고른 상권 하나의 1년 트렌드 — 성장(매출·점포 수), 소비(누가·언제), 관심(키워드), 준비 방향 |

선택 상태는 URL 에 남아요 (`?major=음식점&middle=한식&c=12,301,-&d=12`). 새로고침·링크 공유해도 유지돼요.

## 2. 실행

```bash
cd sangkwon_app
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

- `python -m` 으로 실행해야 설치한 패키지와 실행하는 파이썬이 같아져요 (`No module named 'yaml'` 같은 오류 방지).
- 데이터는 모두 `data/` 폴더 안에 있어요. 경로는 `config/settings.yaml → data`.
- 설정 파일(`config/*.yaml`)을 고친 뒤에는 **앱을 껐다 켜야** 반영돼요 (읽은 설정을 메모리에 저장해 둠). 코드·문구 파일은 브라우저 새로고침이면 돼요.

├─ requirements.txt
├─ .streamlit/config.toml  Streamlit 기본 테마(남색)

├─ config/                 ★ 실제 데이터로 바꿀 때 가장 먼저 보는 곳

│  ├─ trend.py             상권 상세 트렌드 (월별 추이, 최근 vs 기준 비교, 비중 변화) + LLM 입력

## 4. 데이터 흐름

```
[요인 표 xlsx]  ─┐
[상권 지표 csv] ─┼─ loader.py ─ engine.py / factors.py / trend.py ─ views/*.py ─ 화면
[data/area.csv] ─┘
   ↑ columns.yaml        ↑ metrics.yaml · variables.csv        ↑ items.yaml · detail.yaml · theme.css
```

### 4-1. 입력 테이블 (데이터 계약)

| 테이블 | 지금 샘플 파일 | 필요한 역할 (columns.yaml) |
|---|---|---|
| 요인 표 | `data/중분류별 요인 중요도 (음식점).xlsx` | 대분류, 중분류, 변수, 변수명, 순위, 중요도 몫, 방향, 방향 크기(상위 25% vs 하위 25% 예측 매출 차이 %), 신뢰도 / 있으면 shape, threshold, optimum, definition |
| 상권 지표 | `data/final_restaurant_cluster_sl_m.csv` (상권 × 월 × 소분류, 25.08~26.07) | 상권 ID, 월(YYYYMM), 대분류(없으면 settings 의 default_major), 중분류, 가게 수, 매출, 결제 건수 + metrics.yaml 에 적힌 비율 컬럼들 |
| 상권 단위 | `data/area.csv` ← `data/cluster_seoul_t9_202607.gpkg` | 상권 ID, 이름, 구, 격자 수, 중심 좌표 (+ 향후 rent_per_m2, sns_hashtags) |

- 상권 지표가 소분류 단위여도 앱이 중분류로 합쳐서 계산해요. 실제 데이터가 처음부터 중분류 단위면 그대로 돼요.
- 요인 표의 `변수` 값이 상권 지표의 컬럼 이름과 같으면 자동 연결돼요. 다르면 `variables.csv` 의 `metric` 열로 연결해요 (예: `has_delivery → delivery_store_pct`).

### 4-2. 핵심 계산 규칙 (자세한 건 docs/SPEC.md)

| 항목 | 규칙 |
|---|---|
| 비교 기간 | 데이터 마지막 달부터 12개월 (`period_months`). 가게 수만 최근 달 기준 |
| 합치는 방식 | 결제 기준 비율(시간대·주말·회사카드·성별연령 등)은 **매출 가중 평균**, 가게 단위 비율(배달·프랜차이즈 가게 비율 등)은 **가게 수 가중 평균** |
| 서울 보통 | 같은 업종 가게가 최근 달 3곳 이상인 서울 상권들의 중앙값 |
| 가게당 월매출 | 1년 매출 합 ÷ 1년 가게 수 합. 서울 보통 대비 ±% 함께 표시 |
| 동종업계 가게 수·밀집도 | 대분류·중분류 둘 다. 밀집도 = 가게 수 ÷ (격자 수 × 0.0625㎢) |
| 요인 카드 | 요인 표 순위 1~5. 관계 모양이 확인 안 되면(볼록형인데 최적값 없음, 방향이 '뚜렷하지 않음/불안정') "관계 확인 불가" |
| 하이라이트 | 쓸 수 있는 요인만으로 `효과 = 방향 크기 × (상권 값 − 서울 보통) ÷ (서울 상권 p75 − p25)` → 다른 고른 상권 평균과의 차이가 +T 이상이면 가장 유리, −T 이하면 가장 불리 (T = 5). 1곳만 고르면 서울 보통 대비 유리/보통/아쉬움 |
| 상세 트렌드 | 최근 3개월 vs 최근 1년. 데이터가 15개월 이상이면 **최근 3개월 vs 전년 동기로 자동 전환** |
| 상권 이름 | 동 1개 · 대표 도로 (대로 > 로 > 길, 같은 급이면 경계 안 길이 순). 같은 구에서 겹치면 다음 도로로 구분 |

## 5. 자주 하는 수정

| 하고 싶은 것 | 어디서 |
|---|---|
| 화면 문구(행 이름·부제·각주) | `config/items.yaml`, 상세 페이지는 `config/detail.yaml` |
| 요인 이름·설명·칩 이름 | `config/variables.csv` (`name`, `short_name`, `definition`) |
| 코드 안 고정 문구 (예: "▲ 가장 유리 ·") | `views/rows.py`, `views/compare.py`, `core/ui.py` — 따옴표 안 글자만, `{ }` 는 그대로 |
| 비교 표에 행 추가·삭제·순서 변경 | `config/items.yaml` (새 지표면 `metrics.yaml` 에 계산 먼저 추가) |
| 데이터 경로·컬럼 이름 변경 | `config/settings.yaml`, `config/columns.yaml` |
| 기준값 (서울 보통 3곳, T=5, 기간) | `config/settings.yaml` |
| 새 요인 변수 | `metrics.yaml` 에 계산 방법 + `variables.csv` 에 이름·정의·shape |
| 업종(대분류) 추가 (카페·주점 등) | 상권 지표에 해당 대분류 행 추가 + `settings.yaml → data.factor_table` 을 여러 대분류가 들어 있는 요인 표로 교체 |
| 색·글꼴·간격 | `design/theme.css` (기준은 `design/STYLE.md`) |
| 클러스터(상권 경계)가 바뀜 | `python prep/build_area.py` (새 격자 파일이면 `--gpkg <경로>`) (geopandas·requests 필요). 도로·행정동은 처음 한 번만 받고 재사용 |

## 6. 향후 수정되어야 할 부분 (TODO)

### 6-1. 실제 데이터 연결 — 우선순위 높음
- [ ] **데이터 교체**: `settings.yaml → data` 경로, 컬럼 이름이 다르면 `columns.yaml`.
- [ ] **대분류 컬럼**: 샘플 상권 지표에는 대분류 컬럼이 없어 `default_major: 음식점` 으로 간주 중. 실제 데이터에 대분류 컬럼을 넣고 `columns.yaml → metrics_table.major` 에 이름 지정.
- [ ] **'전체' 업종 행**: 중분류 드롭다운의 "전체"는 요인 표와 상권 지표의 `중분류 = 전체` 행을 읽어요. 지금은 행이 없어 대부분 "데이터가 아직 없어요"로 나옴. 모델 결과(요인 표)에 대분류 전체 결과 행 추가 필요. 상권 지표는 행을 넣거나 `total_fallback: aggregate` 로 중분류를 합쳐 계산.
- [ ] **2년 데이터**: 넣으면 상세 페이지 비교가 자동으로 "전년 동기 대비"로 바뀌는지 확인 (`trend.yoy_min_months`). 추이 그래프에 전년 선을 겹쳐 그릴지도 결정.
- [ ] **성능**: 원본 CSV(약 100MB)를 실행할 때마다 읽음. 실제 데이터가 커지면 parquet/DB 로 바꾸고 `core/loader.py → metrics_table()` 만 수정.

### 6-2. LLM 연결 — 화면에 노란 `LLM` 표시가 붙은 자리
- [ ] **매출 요인 하이라이트 한 문장**: `core/factors.py → llm_payload()`(입력, 명세의 JSON 형식) · `llm_sentence()`(지금은 자리 표시). 규칙: 한 문장 50~60자, "~한 사장님께 맞아요"로 끝, 수치 반복 금지, 핵심 키워드 1개 굵게, 인과·보장 표현 금지. few-shot 은 `variables.csv` 의 `high_text`/`low_text` 와 명세 예시 3개.
- [ ] **상세 페이지 헤드라인·준비 방향 제목**: `core/trend.py → llm_payload()` (입력은 `st.session_state["_detail_llm_payload"]` 에 저장됨), 화면 자리는 `views/detail.py → llm()`.
- [ ] 문장이 들어오면 `settings.yaml → llm_placeholder` 자리 표시는 지워도 됨.

### 6-3. 모델 결과 보완
- [ ] **관계 곡선**: 요인 표에는 방향·방향 크기만 있어 하이라이트를 "방향 크기 × 사분위 간격" 직선 근사로 계산 중. SHAP 의존도 곡선(요인 값 → 예상 매출 %)을 받으면 `core/factors.py → Factor.score()` 를 곡선 값으로 교체.
- [ ] **볼록형 요인(주말·오후)**: 지금은 "관계 확인 불가"로 카드·하이라이트에서 제외. 중분류별 최적값을 받으면 `variables.csv`(또는 요인 표)의 `shape=optimum`, `optimum=값` 을 채우면 자동으로 사용됨.
- [ ] **임계값**: 회사카드 20%, 저녁 25% 는 결과 리포트 4-4절의 **음식점 전체 기준**. 중분류별 값이 있으면 요인 표에 `threshold` 컬럼으로 넣기 (요인 표 값이 사전보다 우선).
- [ ] **일식 오후 비중**: 요인 표에서만 방향이 '↑'로 다른 중분류와 반대 — 확인 필요 (지금은 볼록형으로 처리돼 화면 영향 없음).
- [ ] **뷔페**: 학습 가게 수가 적어 신뢰도 '낮음'. 대분류(전체) 요인 행이 생기면 자동으로 "대분류 기준이에요"로 대체됨.
- [ ] **하이라이트 기준 T=5**: 명세상 "확정 필요" 상태.

## 7. 알아두면 좋은 점
- 3년치 parquet(`commercial_area_seoul_restaurant_month_allstores.parquet`)도 검토했지만, 비율 컬럼 집계 방식이 CSV 와 달라(같은 달 2~4%p 차이) 쓰지 않기로 했어요. 2년 데이터를 만들 때 집계 방식을 하나로 맞추는 게 좋아요.
- 세부 업종(소분류) 기준 상대 매출(`rel_sales_mean`)은 화면에서 쓰지 않기로 했어요. "서울 보통"은 모두 같은 중분류 상권들의 중앙값이에요.
- 모든 문구는 "~인 편이에요 / ~일 수 있어요 / ~맞아요"로 끝내고, 인과·보장 표현("이렇게 하면 매출이 오른다")은 쓰지 않는 게 원칙이에요.
